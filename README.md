# 自动模型（Auto Model · 主模型调度版）

[![test](https://github.com/<owner>/dsh-auto-model/actions/workflows/test.yml/badge.svg)](https://github.com/<owner>/dsh-auto-model/actions/workflows/test.yml)
[![npm](https://img.shields.io/npm/v/dsh-auto-model)](https://www.npmjs.com/package/dsh-auto-model)
[![license](https://img.shields.io/npm/l/dsh-auto-model)](LICENSE)

给 DeepSeek Harness 增加一个可切换的 **“自动选择”** 模型：模型选择器里出现 **“自动（Auto）” → “自动选择”**。选中后，由一个**主模型**读取你配置的**副模型清单**（每个副模型的参数、标签与本地配置），为当前任务挑选执行模型；真正的请求由被选中的副模型完成，回复开头会标注本次选用的模型。

> 本插件**只做路由**：工具调用、脚本执行、文件修改、审批与沙箱全部沿用当前会话原有机制。

```
用户消息 ──▶ 主模型（路由器：只收任务摘要 + 副模型清单）
                 │ 输出 {"route":"provider/model","reason":"…"}
                 ▼
           副模型（执行请求、调用工具、生成回复）
                 │
                 ▼
   回复 = 🧭 自动模式｜主模型 X｜任务 文本任务（文本+快速） → 执行 Y（理由） + 副模型的实际输出
```

## 安装

```bash
# npm（推荐）
dsh plugin --profile web add dsh-auto-model

# GitHub（可固定 commit）
dsh plugin --profile web add github:<owner>/dsh-auto-model#<40位commit>
```

装完**重启 Harness**（Host 插件在启动时加载；只刷新页面不足以换掉旧的 Host 逻辑）。

## 使用

1. 安装/更新本插件后**重启 Harness**（Host 插件在启动时加载；只刷新页面不足以换掉旧的 Host 逻辑）。
2. 打开任意会话的模型选择器（输入框旁的模型按钮，或 `/model`），选中 **“自动（Auto） → 自动选择”**。
3. 打开 **设置 → 自动模型**：
   - **主模型**：负责挑选执行模型的模型（自己不回答用户）。建议选响应快、指令跟随稳定的模型。
   - **副模型清单**：主模型只能从这里选。顺序是提示与重试顺序；每行可勾选 **免费**、设置多个 **标签**。
   - **自定义标签**：在清单上方添加自己的标签（如 `sql`、`法律`），添加后可作为任意副模型的标签。
   - **能力标签**：只是给主模型的判断依据（软偏好），由主模型决定是否采用，不做硬过滤。
   - **优先使用免费模型**：默认关闭；开启后优先选免费副模型，免费不可用或调用失败时自动换其他模型。
   - **兜底模型**：副模型全部不可路由时使用。
   - **在回复中显示本次选用的模型**：默认开启。
   - **向模型提示中提供 API Key 明文**：默认关闭，见下文。
   - **高级**：上下文窗口覆盖（0 = 取候选最小值）、最大输出 tokens（0 = 模型默认）。

## 标签与能力（软偏好）

**能力是硬约束，标签只是偏好。**

### 能力硬约束（自动推导）

- 带图片的请求：模型 `inputModalities` 必须包含 `image`；
- 纯文本请求：所有模型都可参与——视觉理解模型本身也能生成文本，不会被排除；
- DSH 只暴露 `inputModalities`，没有 `outputModalities`；文生图通常走工具，见下文。

### 输入 / 输出类型（只是模态类型）

| 类型 | 含义 |
|---|---|
| `text` | 文本 |
| `image` | 图片 |
| `audio` | 音频 |
| `video` | 视频 |

每个副模型分别声明 **输入类型**（能接收什么）和 **输出类型**（能产出什么）。典型：

- 普通对话模型：输入 `text`，输出 `text`；
- 视觉理解模型：输入 `text + image`，输出 `text`；
- 文生图模型：输入 `text`，输出 `image`；
- 图生图模型：输入 `image`，输出 `image`。

### 能力标签（模型擅长什么）

| 标签 | 含义 |
|---|---|
| `vision` | 图像理解（看图、截图、OCR） |
| `image-gen` | 文生图 |
| `image-to-image` | 图生图 |
| `multimodal` | 多模态（跨模态理解/生成） |
| `audio-gen` | 文本生成音频 |
| `video-gen` | 文本生成视频 |
| `coding` | 代码生成与修改 |
| `reasoning` | 复杂推理 |
| `math` | 数学计算 |
| `long-context` | 长上下文 |
| `fast` | 响应快 |
| `tools` | 擅长工具调用 |
| `ocr` | 文字识别 |
| `translation` | 翻译 |
| `summarization` | 摘要 |
| `creative` | 创意写作 |
| `agentic` | 自动化/多步执行 |

设置页按 **输入类型 / 输出类型 / 能力** 三行分别显示，标签会自动换行，不会挤在同一行。

### 自定义标签

- 在 **设置 → 自动模型 → 自定义标签** 输入名称（字母、数字、中文、`-`、`_`，最长 24 字符，最多 20 个）；
- 添加后出现在每个副模型的 **能力** 行里，可像内置能力标签一样勾选；
- 自定义标签只参与排序和提示，不会自动出现在任务标签里（任务标签只由内置规则推导）。

### 忘记打标签会怎样

不会导致模型不可用，只是**排序靠后**：

- 没有任何能力标签的模型按“通用”参与选择，仍可被主模型选中；
- 路由提示会告诉主模型：「部分模型可能没有用户标签，不要仅因缺少标签就排除，请结合名称、输入/输出类型和上下文窗口判断」；
- Host 还会从**模型元数据和名称**自动推导一部分标签作为兜底（提示里标注“自动推导”）：
  - 输入含图片 → `vision` + `multimodal`；含音频/视频 → `multimodal`
  - 名称含 `coder`/`codex`/`code` → `coding`
  - 名称含 `reason`/`thinking`/`r1`/`o1`/`o3`/`qwq` → `reasoning`
  - 名称含 `math` → `math`
  - 名称含 `flash`/`mini`/`lite`/`turbo`/`small`/`nano` → `fast`
  - 上下文窗口 ≥ 128k → `long-context`
- 输入模态的硬约束始终以宿主 `inputModalities` 为准，忘了 `vision` 标签也不会把纯文本模型派去处理图片；
- 设置页会显示标签覆盖情况（如 `2/3 个副模型已标注能力标签`）；未标注的模型带“未标注”标记并以警告色提示，方便你补全。

### 任务标签（自动推导）

| 条件 | 加入的能力标签 |
|---|---|
| 请求最新消息带图片 | `vision` |
| 用户要求生成图片（“画一张…/生成图片/文生图/draw an image”） | `image-gen` |
| 带图片 + 要求生成图片 | `image-to-image` |
| 带图片 + 本轮已有工具调用 | `multimodal` |
| 本轮历史已有工具调用 | `tools` |
| 估算上下文 ≥ 48000 tokens | `long-context` |
| 估算上下文 ≤ 6000 tokens 且无图片 | `fast` |

### 排序

- **只排序、不排除**：开启免费优先时先按免费分组，再按“能力匹配 + 输入/输出模态匹配”排序；主模型看到“推荐在前、其他在后”的完整清单，并能从任意模型中选择。
- **没有严格模式开关**：能力标签只是给主模型的判断依据，是否采用由主模型决定；输入模态（带图必须支持图片）仍是硬约束。
- 路由行会显示任务能力标签，例如：`🧭 自动模式｜主模型 deepseek-flash｜任务 图像理解（图像理解） → 执行 hbec/qwen25-72b（免费）`。
- 旧配置自动迁移：`text → inputs:[text]`、`vision → inputs:[image] + tags:[vision]`、`multimodal → inputs:[image] + tags:[multimodal]`、`image-gen → outputs:[image] + tags:[image-gen]`，旧 `category` 同理。

## 文生图 / 图生图

DSH 没有 `outputModalities`，文生图由**工具**完成（模型调用画图工具，工具返回图片链接/附件）。因此：

- 给适合画图的模型设置 **输出类型含 `image`**、能力标签含 `image-gen`（文生图）/ `image-to-image`（图生图）+ `tools`，例如：
  ```yaml
  - provider: hbec
    model: qwen25-72b
    inputs: [text, image]
    outputs: [text, image]
    tags: [vision, image-gen, image-to-image, multimodal, tools]
    free: false
  ```
- 用户说“画一张猫”时，任务标签会带上 `image-gen`，路由提示里也会注明“用户想生成图片：是 / 需要的输出类型：文本+图片”，主模型会优先选输出含图片、带 `image-gen`/`image-to-image`/`tools` 的模型；
- 模型本身只负责理解需求并调用工具，**不需要直接输出图片**；
- 如果你有独立的文生图服务（不是 LLM），它通常以工具形式注册，而不是副模型；把调用它的通用模型标上 `image-gen` + `tools` 即可。

## 免费标记与“优先使用免费模型”

每个副模型都有一个 **免费** 勾选框（由你自己声明，插件不探测真实账单）：

- 清单行内可直接勾选/取消；添加新模型时也可以先勾“免费”再添加。
- 开启全局 **“优先使用免费模型”** 后：
  1. 先按任务能力过滤：模型上下文窗口必须不小于本次请求的估算大小，并且输入模态要匹配（图片任务必须支持图片）。
  2. 主模型的候选清单把可用免费模型排在前面，并收到“能胜任就优先免费，否则选付费”的规则和每个模型的 `计费：免费/付费` 标记。
  3. 任何一个副模型在**产生任何可见输出之前**失败（额度、鉴权、限流、上下文超限、网络等）时，插件会依次重试其他候选，并在回复里插入一行：`⚠️ X 调用失败（原因），已切换到 Y`。
  4. 刚失败的模型会冷却 2 分钟，下一轮路由先跳过它，避免反复撞同一个错误。
- 路由行会标注 `（免费）`，例如：`🧭 自动模式｜主模型 deepseek-flash｜任务 文本任务（文本+快速） → 执行 zai-free/glm-4.7-flash（免费）`。
- 如果模型已经开始输出再失败，则不会中途换模型（避免重复/断裂内容），按普通失败处理。
- 关闭该选项时，免费标记只作为提示信息，不影响选择。

## 主模型看到什么

每次需要决策时，插件给主模型发一条**独立的短提示**（**只发任务摘要，不发送完整会话上下文、不发送图片**），包含：

| 内容 | 示例 |
|---|---|
| 副模型路由 | `hbec/qwen25-72b-h6b2` |
| 参数 | 名称、上下文窗口、最大输出、输入类型（文本/图片）、输出类型（文本/图片）、计费（免费/付费）、能力标签（如 `图像理解+多模态` 或 `通用`） |
| 本地配置 | `baseURL`、协议（`openai-completions` 等）、`apiKeyEnv`（如 `HBEC_API_KEY`）以及该凭据**是否已配置** |
| 任务摘要 | 用途（普通/压缩/会话标题）、任务标签（`text+fast` 等）、是否含图片、用户是否想生成图片、本轮是否已调用工具、请求大小估算（tokens）、用户最后一条消息（截断）、助手最近一条消息、最近工具名 |
| 选择规则 | 有图必须选支持图片的模型；标签匹配优先但不强制；文生图优先 `image-gen`/`tools`；轻量任务优先快/便宜；复杂任务优先大上下文/强模型；开启免费优先后能胜任就选免费；只能从清单里选 |

主模型只需输出一行 JSON：

```json
{"route":"hbec/qwen25-72b-h6b2","reason":"长文推理，选 72B"}
```

解析失败、超时或主模型不可用时，插件会自动回退到清单里第一个可路由（且满足图片能力）的副模型，并在回复里注明“主模型未给出有效决策，已自动回退”。

## 执行时使用完整上下文

路由摘要只用于**选择模型**；真正转发给副模型的请求会**原样携带完整会话上下文**：

- 完整的 `messages`（全部历史、工具调用与工具结果、图片附件）；
- 原始 `tools`、`temperature` 等请求参数；
- 不做任何截断或摘要。

因此副模型看到的是和用户实际对话一致的内容，路由提示的“精简”只影响主模型那一次选型调用。

## 失败、重试与主模型兜底

自动模式不会把底层错误直接甩给用户：

1. **预过滤**：上下文估算超出模型窗口、凭据缺失、刚失败过的副模型，会在给主模型看清单之前就被剔除。
2. **逐个重试**：选中的副模型在**产生任何可见输出之前**失败时，按清单顺序（开启免费优先时先免费后付费；上下文超限时优先换更大窗口的模型）自动重试下一个，并在回复里插入一行：
   `⚠️ hbec/qwen25-72b-h6b2 调用失败：上下文超出模型上限，已切换到 zai-free/glm-4.7-flash`
3. **主模型接管**：所有副模型都失败（或根本没有可用副模型）时，改用**主模型**带着完整对话完成本轮回复，并提示：
   `⚠️ 所有副模型都调用失败：…。已切换为主模型 deepseek-account/deepseek-flash 完成本次回复。`
4. **最终保底**：主模型也失败时，仍然输出一条正常回复（而不是裸的 `本轮运行失败`），列出每个模型的可读失败原因，并提示去检查 API Key / 额度 / 上下文限制。该回复以正常 `stop` 结束。
5. 失败过的模型会冷却 2 分钟，下一轮先跳过；连续失败不会反复撞同一个错误。
6. 已经输出部分内容后再失败不会中途换模型（避免内容重复或断裂），按普通失败处理。

后台辅助请求（压缩、会话标题）不会显示这些提示，也不会触发主模型兜底：它们由其他子系统消费，失败时只返回错误状态。

## 路由与缓存

- **每个用户轮次决策一次**：同一轮里的多步工具调用复用同一个选择；任务中途出现图片时会重新判定并强制切到支持图片的副模型。
- 辅助请求（压缩 `compaction`、会话标题 `session-title`）**不调用主模型**，直接使用清单里第一个可路由的副模型，也不显示路由行。
- 会话日志里的路由仍是 `auto/auto`，不会因为内部分流反复出现 `[model changed: …]`；路由信息体现在回复正文里。
- 图片能力以 `resolveModelInfo().inputModalities` 为准；手工写在 `llm-pi-ai` 里的模型默认是纯文本，需要在 **设置 → 模型 → 该提供方 → 该模型 → 输入类型** 勾选 **Image**（例如 `hbec/qwen25-72b`、`zai-free/glm-4.6v-flash`）。

## 关于 API Key（「不支持直接调用时把 key 告诉模型」）

本插件**通过 DSH 自己的 `ctx.llm.stream` 直接调用副模型**，因此正常情况下不需要把 Key 交给任何模型：

- 默认 `exposeApiKeys: false`：路由提示里只出现**环境变量名**以及“已配置/未配置”，真实 Key 不会离开进程。
- 如果确实需要模型自己带 Key 去直连，在设置里打开 **“向模型提示中提供 API Key 明文”**。开启后，解析到的 Key 会写进主模型的路由提示（`密钥：<真实值>`）。

这个选项的主要用途是**让主模型构建本地外部脚本**，例如：

- 用 Python / curl 写一个脚本，直接调用某个提供方的 API（批量转写、格式转换、特殊采样参数等 DSH 路由覆盖不到的场景）；
- 为特殊处理任务生成脚本，并在脚本里选用合适的模型（结合上面的输入/输出类型与能力标签）；
- 主模型在兜底接管时也可以按同样思路，用脚本完成副模型无法完成的任务。

**注意：这会把密钥发送给主模型提供方，存在泄露风险**，仅在明确需要时开启。主模型只是“写”脚本，脚本要真正执行仍由被选中的模型通过正常工具调用发起，并走当前会话的审批（见下节）。

## 脚本与审批

本插件**只做路由**：选择副模型、把完整请求转发给副模型，其余行为（工具调用、命令执行、文件修改、审批、沙箱）全部沿用当前会话原有的机制，没有任何插件私有的执行通道。

- 主模型拿到 Key 后可以“写”脚本，但脚本要真正执行，仍需由被选中的模型通过正常工具调用发起，并走当前会话的审批；
- 插件不会绕过 DSH 的审批，也不额外提供 `allowScripts` 之类的开关；
- 因此 `exposeApiKeys` 的作用仅限于：让主模型在规划时知道 Key 可用，从而决定是否走“写脚本 + 工具调用”的路线。

## 已知限制

- 主模型每轮多一次轻量调用（约几百 token）；路由提示只含任务摘要与清单，**不含完整会话上下文**。
- 能力标签只是排序依据，由主模型综合判断选择，不存在硬过滤导致“没有可用模型”的情况。
- 请求大小是字符/图片估算，不是精确 token 计数；“能力判断”还包含主模型自己的判断。
- 模型开始输出后报错不会自动换模型；只有“尚未输出任何内容”的失败才会自动切换。
- 主模型兜底会把完整对话交给主模型；如果主模型也超出上下文或凭据失败，就会得到那条“所有模型均失败”的可读回复。
- 主模型只看到任务摘要（最后一条用户消息 + 最近助手消息 + 工具名），不适合需要通读整个上下文的细粒度决策；副模型执行时仍会收到完整上下文。
- 计费/用量按 `auto/auto` 记录；token 用量来自真实副模型，图像成本估算可能中性。
- 会话系统提示里的 `{{model}}` 显示为 `auto`，而不是本次实际路由到的模型。
- 上下文窗口默认取候选最小值（安全但可能偏小），可在设置里覆盖。

## 架构与文件

- `index.js`：Host 插件。注册虚拟 LLM 适配器 Provider `auto`（模型 `auto`）；在 `adapter.stream` 里：
  1. 先按需调用主模型得到决策（结果按“轮次 + 图片/文生图/工具状态 + 任务标签 + 计费偏好 + 清单”缓存）；
  2. 用 `ctx.llm.stream({provider, model, ...})` 转发给副模型；失败时按顺序重试其他候选（上下文超限时优先更大窗口），全部失败后由主模型接管，主模型也失败则输出可读的失败总结；
  3. 若开启展示，把 `🧭 自动模式｜…`、失败切换提示与接管提示作为额外的文本块插入流的前面，其余分片 index 整体后移。
- `client.js`：浏览器设置页（`settings.section`，id `auto-model`），编辑主模型、副模型清单及其输入/输出/能力标签、自定义标签、兜底、免费优先开关、展示与 Key 开关、高级参数。
- `cordis.patch.yml`：bundle 插入行（行 id = 设置命名空间 `auto-model`），默认主模型 + 副模型清单按本机实际 provider/model 填写。
- `locale/{zh,en}.json`、`icon.svg`：插件管理器显示元数据。
- `test/router.test.mjs`：路由决策单元测试（mock 主模型与副模型）。

配置持久化到 `$DSH_HOME/profiles/<profile>/cordis.patch.yml` 中 `auto-model` 行的覆盖里；改完后下一轮请求即生效。
